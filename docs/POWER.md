# Power budget

Estimate of average current and battery life. It is a **model**: the sleep currents come from datasheets, and the active-phase currents and durations are **assumptions** until session 5 measures them on the board with a PPK2. Every number lives in [`tools/power_params.json`](../tools/power_params.json) with its source. The tables below are generated by [`tools/power_budget.py`](../tools/power_budget.py), and a CI test fails if they no longer match the parameters.

## What the firmware does to get there

| Mechanism | Where |
|---|---|
| RTOS tick on **LPTIM1 clocked by the 32.768 kHz LSE**, which keeps counting in Stop 2 (SysTick stops) | `power/src/pm.c` |
| **Tickless idle**: when every task is blocked, the idle task programs the LPTIM compare for the next timeout (up to ~15.6 s, then it re-arms) and sleeps | `vPortSuppressTicksAndSleep()` |
| **Stop 2** when no peripheral needs the high-speed clocks; **Sleep** (WFI) while a lock is held (modem UART receiving, console in use) or the gap is under 8 ticks | `pm_choose()` |
| Elapsed time is always read **from the counter**, never by counting interrupts, so a late wake-up cannot lose ticks. The arithmetic is unit-tested on the host, including the counter wrap and the compare-too-close case | `power/src/lowpower_calc.c`, `tests/host/test_lowpower_calc.c` |
| Wake-up sources in Stop 2: LPTIM1 (next deadline), EXTI0 (LIS2DH12 INT1, motion), EXTI3 (console RX start bit) | `app/src/motion.c`, `app/src/console.c` |
| Accelerometer in low-power mode at 10 Hz with a high-pass-filtered threshold on INT1, **latched** so a short shake is not lost while the MCU wakes up | `drivers/src/lis2dh12.c` |
| Modem powered only for a report (`AT+QPOWD` afterwards), or PSM requested with `AT+CPSMS` (T3412/T3324 encoded per 3GPP TS 24.008) | `modem/src/bg95.c`, `modem/src/psm.c` |
| GNSS engine stopped (`AT+QGPSEND`) as soon as there is a fix or the 90 s timeout expires | `modem/src/bg95.c` |

## Reading the numbers

- **The sleep floor is under 20 µA** (about 8 µA with the modem switched off, about 12 µA with it in PSM). That is the figure the hardware and the Stop 2 work control.
- **The average current is set by the reports, not by the sleep floor.** One report costs 1.5–2.2 C (mostly the 30 s GNSS fix and the LTE registration), which is as much charge as 1.5–3 days of sleep. With a report every hour the average is around 0.4–0.6 mA, far above the floor.
- So the levers, in order: **report less often**, **shorten the GNSS fix** (assisted GNSS / XTRA data, keeping ephemeris valid between fixes, skipping the fix when the accelerometer says the device has not moved), **avoid re-registration** (PSM instead of power-off saves the attach), and only then the sleep floor.
- PSM wins at every interval in this model because skipping the registration saves more than its 3.9 µA costs. Below about one report per day the two converge. Whether the network actually grants the requested PSM timers is only known on a real SIM (`AT+QPSMS?`).
- The model ignores extra reports while moving (every 5 min by default in `app/src/tracker_app.c`), battery self-discharge, temperature, and the BG95's peak currents. A Li-SOCl2 bobbin cell cannot deliver the BG95's transmit peaks on its own and needs a buffer capacitor or a hybrid layer capacitor.

## How session 5 will check it

1. Stop 2 floor with the modem off and the accelerometer on: PPK2 in ammeter mode on the NUCLEO's IDD jumper (JP6), debugger disconnected (`DBG_STOP` costs current), unused pins analog.
2. One full report cycle per strategy, integrated charge, compared with the table above.
3. Replace the assumptions in `power_params.json` with the measurements and regenerate this page.
